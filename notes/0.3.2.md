mpv and yt-dlp now ship inside Spiceity. Nothing is downloaded on first run, and every installation of this release runs exactly the same binaries.

## Why that matters

Spiceity used to fetch these two programs the first time it started, into your application data folder. That worked — until it didn't, on one machine, where playback started and stopped about a second later with no sound, while the same version played perfectly elsewhere.

Fetching at run time makes every installation subtly different: a different mpv build depending on the day you installed, an executable appearing in AppData for antivirus to form its own opinion about, and — because the mpv builds publish no checksums — no way to know the copy that arrived was the copy that was sent. A fault that cannot be reproduced cannot be fixed.

One release now carries one mpv and one yt-dlp, covered by the installer's own checksum, installed alongside the program rather than in your profile.

yt-dlp is the one exception: if Spiceity later downloads a newer one, that copy wins. YouTube changes, and a yt-dlp frozen at release time stops working long before the next release.

## Playback can now say what went wrong

mpv was being started in a way that discarded everything it printed, so when it stopped, it stopped silently — and Spiceity treated a player that had crashed exactly like a track that had finished. The queue moved on, nothing appeared on screen, and there was no way to find out why.

mpv now keeps a log, and the line it stopped on is shown to you. A player that fails is reported as a failure; a player that reaches the end of a track still moves the queue along, as it should.

## Which file

| Platform | File |
| --- | --- |
| Windows | `Spiceity-0.3.2-windows-x64-setup.exe`, or the `.msi` for deployment |
| Debian, Ubuntu, Mint | `spiceity_0.3.2_amd64.deb` |
| Fedora, RHEL, openSUSE | `spiceity-0.3.2.x86_64.rpm` |
| Android | `Spiceity-0.3.2.apk` |

The Windows packages are larger than before — about 340 MB against 273 MB — which is mpv and yt-dlp being in the box rather than fetched afterwards. The Linux packages are unchanged: there is no portable mpv for Linux, and the package manager is the right place to get it.

**Close Spiceity before installing.** The installer cannot replace files the running program is holding open.

```
sha256sum --check --ignore-missing SHA256SUMS.txt
```

## Updating

Download it from this page. Spiceity's own updater cannot see this release: it asks GitHub's `/releases/latest`, which answers 404 for a private repository, and Spiceity reads that as being up to date.
