Lyrics that follow the song, a sleep timer on both players, and a day of testing on a real phone.

## Lyrics keep up with the music

The line being sung sits in the middle of the screen, large and bright, and the page moves with the song — the way every other player does it, and the way a phone on a desk across the room has to work. Scroll by hand and it waits a few seconds, then finds its place again. The lyrics provider you pick in Settings is now the one that is read; before, it was offered there and ignored.

## Sleep timer, on the phone and the desktop

Tap the moon on either player. Pick 15, 30, 45, 60 or 90 minutes, the end of the current track, or type any number. It remembers what you chose. The countdown shows in the header and can be extended or stopped from the same place. The desktop had no sleep timer at all; the phone had one that started whatever length Settings said.

The deadline is a moment on the clock rather than a count of seconds, so a phone that dozes on the bedside table does not stretch half an hour into a whole one.

## On the phone

- **The splash is drawn every time.** It used to be left to the launcher, which on some phones showed the icon and on some showed nothing.
- **The player bar can sit at the top**, under the status bar, as it has been able to on the desktop all along. Settings → Customization → Player bar.
- **No signal is said as no signal.** "Unable to resolve host youtubei.googleapis.com" now reads *No internet connection. Check your connection and try again.* — from the extractor, the player, and the home and search screens alike.
- **A track that fails to play no longer shows the previous track's position**, and its spinner no longer flickers while it resolves.

If your phone had the September 16 build, customizations saved but did nothing on screen. That build predates the wiring; this one applies and keeps every one of them — tested by changing five, killing the app, and relaunching.

## On the desktop

- **Sleep timer** beside the Connect button on the player bar.
- A track that fails to resolve now silences the one before it, instead of leaving it playing under an error about a different song.

## Which file

| Platform | File |
| --- | --- |
| Windows | `Spiceity-0.3.3-windows-x64-setup.exe`, or the `.msi` for deployment |
| Debian, Ubuntu, Mint | `spiceity_0.3.3_amd64.deb` |
| Fedora, RHEL, openSUSE | `spiceity-0.3.3.x86_64.rpm` |
| Android | `Spiceity-0.3.3.apk` |

Windows packages carry mpv and yt-dlp inside them, so nothing has to be fetched before the first track plays. **Close Spiceity before installing** — the installer cannot replace files the running program holds open.

## Verifying a download

```
sha256sum --check --ignore-missing SHA256SUMS.txt
```

The APK is signed with Spiceity's release key, certificate fingerprint:

```
46:CF:8B:96:C4:37:49:7A:93:AF:76:2B:91:94:AD:11:09:5D:D6:4A:B6:AB:EA:E9:60:C0:A5:98:C5:63:49:ED
```

A debug-signed build already on a phone (from a `gradlew installDebug`) has to be uninstalled first; Android will not replace it with this one.

## Updating

Download it from this page. Spiceity's own updater cannot see this release: it asks GitHub's `/releases/latest`, which answers 404 for a private repository, and Spiceity reads that as being up to date.
