A fix for opening Noctorium from the menu on Linux once the Noctorium CLI is installed.

## Fixed

- **On Arch, Noctorium did not open from the menu once the Noctorium CLI was installed.** The Arch package
  put Noctorium on the PATH as `noctorium` and its menu entry started it by that name — but `noctorium` is the
  CLI too, and the CLI, installed in `~/.local/bin`, comes first. So the menu started the CLI, which had no
  terminal to show itself in and quietly gave up. The menu entry now names Noctorium by its full path.
- **The Noctorium CLI, started where there is no terminal** — from a menu, a shortcut or a launcher — now
  opens the Noctorium window instead when Noctorium is installed, and otherwise says at once that it needs a
  terminal, rather than starting everything and stopping without a word. This also mends a menu entry from
  an older Arch package as soon as the CLI updates itself.

## Worth knowing

- On Arch, Noctorium's own command in a terminal is now `noctorium-desktop`; `noctorium` is the CLI, as on
  every other system.
- The .deb, the .rpm, the AppImage, the Flatpak, Windows and the Mac were not affected: their menu entries
  and shortcuts already named Noctorium by its path. Every Linux package is now checked for that before a
  release.
- Noctorium itself, on the desktop and the phone, is the same as in 0.10.0; only the number has moved.
