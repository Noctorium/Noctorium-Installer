The PC installer opens a window instead of a console. The player itself is exactly 0.4.1.

## The installer has a window

`Noctorium-Installer-windows-x64.exe` and `noctorium-installer-linux-x64` used to be console programs: you
ran one and it immediately began, narrating itself in a terminal. They now put up a window in Noctorium's
own colours, with Noctorium's own mark on it.

The useful difference is not that it is prettier. It is that it **asks first**. The window shows which
version it found and how much it is about to download, and waits to be told to go ahead — the console
version committed you the moment you started it. After that: a progress bar, then the install, then
"Noctorium is installed."

Everything it did before, it still does. The download is checked against the checksum published with the
release before anything is run, and a file that does not match is deleted rather than executed. It still
skips its own files in a release, so it never offers to install itself.

Three smaller things:

- On Windows, double clicking it no longer flashes up a console window first.
- A failed lookup offers **Try again** rather than only Close. Most of what goes wrong between asking
  GitHub and having a file is a network that was briefly not there.
- `--cli` still gives you the old text version, and a machine with no display — over ssh, where `DISPLAY`
  and `WAYLAND_DISPLAY` are both unset — gets it automatically without being asked.

It costs size. A window toolkit is not free, and these went from 1.4 MB to 4.0 MB on Windows, and from
1.7 MB to 6.9 MB on Linux, which carries both X11 and Wayland. That seemed the right trade for the first
thing anybody sees of Noctorium, usually before they have any reason to trust it.

## The player is unchanged

Noctorium itself is built from exactly the source 0.4.1 was built from — the same commits in
Noctorium-Base, Noctorium-Desktop and Noctorium-Mobile, with the same core pinned. Nothing in the player
is different. Playback, themes, pinning, track edits, SponsorBlock skipping, accounts and scrobbling all
behave as they did.

So if you already have 0.4.1, this release gives you nothing but a better installer, and you can ignore
it. It is a whole release because the installers are published as part of one: attaching new files to
0.4.1 after the fact would leave its `SHA256SUMS.txt` no longer describing its own contents, and anybody
who checked that release would find it had quietly changed underneath them.

One consequence worth stating, in case somebody compares: the checksums below are **not** the same as
0.4.1's, even though the source is. Neither Gradle nor jpackage nor Rust produces bit-identical output
from one build to the next — timestamps and build paths go into the files — so identical source gives
different bytes. The signing key has not changed, and that is the thing worth checking.

## Which file

| Platform | File |
| --- | --- |
| Windows | `Noctorium-0.4.2-windows-x64-setup.exe`, or the `.msi` for deployment |
| Debian, Ubuntu, Mint | `noctorium_0.4.2_amd64.deb` |
| Fedora, RHEL, openSUSE | `noctorium-0.4.2.x86_64.rpm` |
| Android | `Noctorium-0.4.2.apk` |

Or take an installer above and let it choose for you. The desktop packages carry their own Java runtime
and their own Chromium for the sign-in window; the Windows ones carry mpv and yt-dlp as well, so nothing
has to be fetched before the first track plays. **Close Noctorium before installing over it** — an
installer cannot replace files a running program holds open.

## Verifying a download

```
sha256sum --check --ignore-missing SHA256SUMS.txt
```

The APK is signed with the same release key as every version before it, certificate SHA-256 fingerprint:

```
46:CF:8B:96:C4:37:49:7A:93:AF:76:2B:91:94:AD:11:09:5D:D6:4A:B6:AB:EA:E9:60:C0:A5:98:C5:63:49:ED
```

A debug-signed build already on a phone has to be uninstalled first; Android will not replace it with a
release-signed one.
