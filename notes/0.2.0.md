The first published Spiceity. One music player for YouTube Music and SoundCloud, with Spotify read-only, on Windows, Linux and Android.

## What is in it

**Spiceity Connect.** Your devices find each other on the same network and hand playback between themselves, the way Spotify Connect does — except only between devices signed in to the same Spiceity. Discovery is a UDP broadcast on the local network; every request is signed with a key derived from your account, so a device on your Wi-Fi that is not yours cannot drive your music.

**It updates itself.** Spiceity asks GitHub once at launch and offers what it finds. Every download is checked against `SHA256SUMS.txt` from this same release before anything runs, and a release without checksums is refused outright. A copy running from an unzipped folder is told about the update and sent here instead of being handed an installer, because running one over a folder that was never installed leaves two copies on the machine.

## Which file

| Platform | File |
| --- | --- |
| Windows | `Spiceity-0.2.0-windows-x64-setup.exe`, or the `.msi` for deployment |
| Debian, Ubuntu, Mint | `spiceity_0.2.0_amd64.deb` |
| Fedora, RHEL, openSUSE | `spiceity-0.2.0.x86_64.rpm` |
| Android | `Spiceity-0.2.0.apk` |

The desktop packages are large — around 270 MB — because each carries its own Java runtime and its own copy of Chromium for the SoundCloud sign-in window. Nothing has to be installed first.

## Verifying a download

```
sha256sum --check --ignore-missing SHA256SUMS.txt
```

The APK is signed with Spiceity's release key. Its certificate fingerprint is:


If you installed a test build of Spiceity before this release, it was signed with Android's debug key and this one cannot replace it. Uninstall the old one first. This is a one-time cost of the release key existing, and it will not happen again.
